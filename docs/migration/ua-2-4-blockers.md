# UA-2-4 Blocker 记录

## B1 软删除双重可见（001/002/003）

| 字段 | 值 |
|------|-----|
| 影响 Case | UA-2-4-001, UA-2-4-002, UA-2-4-003 |
| 规格要求 | 软删除后的位号在 `list_tags` 中消失，仅出现在 `list_recycle_tags` |
| 实际结果 | 软删除后的位号同时出现在 `list_tags`（active）和 `list_recycle_tags`（recycle） |
| 是否稳定复现 | 是（每次均双重可见） |

### 分析

产品 `batchDeleteLogic` 接口仅将 tag 标记为回收状态但不从正常查询中移除。`list_tags` 不过滤该标记，因此软删除后依然可见。规格要求在 001/002/003 中对回收站可见性做严格断言时将 FAIL。

## B2 软删除后仍可写（009）

| 字段 | 值 |
|------|-----|
| 影响 Case | UA-2-4-009 |
| 规格要求 | 软删除后 `write_tag_values` 应失败或不生效；OPC UA 源值不变 |
| 实际结果 | `write_tag_values` 成功返回，值传播到 OPC UA 源 |
| 是否稳定复现 | 是（每次写操作均成功传播） |

### 分析

产品在软删除后不阻断下行写入路径，`write_tag_values` 仍经正常管道推送。规格要求在 009 中断言源值不变时将 FAIL。

## 影响总览

| 维度 | 值 |
|------|-----|
| 阻塞迁移 | UA-2-4-001/002/003/009 共 4 道 |
| blocker 引起 FAIL | 4 |
| 不受影响 | UA-2-4-004（身份保持）, 005~008（spec_pending） |
